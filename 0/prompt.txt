I reviewed all five repos plus AIKit's actual implementation (not just its README). AIKit already covers a lot — Tier-1 token budgeting, AST symbol map + import-cycle graph, disruption ledger, secret scan, reachability, dogfood, commit verification, project registry. The useful ideas are the ones that turn **instructions into observable, deterministic CLI output** without adding dependencies.

## Verdict

Five candidates fit AIKit's zero-dependency, stdlib-only, CLI-first design. Two are cheap aggregators over gates AIKit already has; one is the big differentiator; two are smaller extensions.

| # | Idea | Source | AIKit gap today | Fit | Effort |
|---|---|---|---|---|---|
| 1 | `aikit context` — per-host context footprint & trend | dsh-context, claude-howto | `estimate_tokens` exists (`scripts/sync_principles.py:47`) but only audits Tier-1; no composition, no history, no skill/knowledge accounting | High | S–M |
| 2 | `aikit audit` — harness readiness + config security + drift snapshot | ruflo MetaHarness | Gates exist but are separate commands; `.claude/settings.json:1` only denies ledger edits; no snapshot/regression detection | High | S |
| 3 | `aikit graph query/path/explain` — explained-edge code graph | graphify | `knowledge/codebase_map.md` is a flat symbol catalog; `update_knowledge_base.py:547` builds only an import graph for cycle detection | High | M–L |

## Top four in detail

**1. `aikit context` (dsh-context is the strongest conceptual match)**
dsh-context's whole thesis — show *what the agent is carrying*, split by composition, and how it changed — is missing from AIKit even though AIKit has the exact budget arithmetic. Build `scripts/context_report.py`:
- Enumerate always-on surfaces: the 8 Tier-1 files, `.agents/rules/domain.md`, each `SKILL.md`, `knowledge/*.md`, `README.md`.
- Classify into rules / domain / skills / knowledge / codebase-map; report tokens via the existing `chars // 4` calibration (`sync_principles.py:47`).
- Compare against `TARGET_TOKEN_BUDGET = 1600` and the 22.5k README ceiling.
- `--json` with stable codes, and `--history N` re-reading files at the last N commits via `git show` for a trend. No compaction UI needed — AIKit's "compaction event" is the ledger checkpoint.
This is a natural extension of P-001/P-017, not a new subsystem.

**2. `aikit audit` (ruflo MetaHarness)**
Almost free: aggregate `sync_principles --check`, `update_knowledge_base --check`, `check_secrets --all`, `check_reachability`, ledger validity, README parity, test-budget pass/fail, and host-file parity into one report with one exit code. Then add what ruflo calls "scan tool configs": check `.claude/settings.json`, `opencode.jsonc`, and each host rule file for dangerous permissions (e.g. `bypassPermissions`, editing a ledger) and for unresolved placeholders. Store a hash snapshot in `.agents/` so drift between runs is visible.
Caution: treat it as a **checklist with failures**, not a 1–100 score — P-001 R8 says report only failed items, and a score invites gaming a gate (P-000).

**3. `aikit graph` (graphify)**
This is the highest-value but largest piece. AIKit already parses Python with `ast`; extend the extractor to emit `knowledge/codebase_graph.json`:
- Nodes: module, class, function/method (reuse the symbol logic).
- Edges: `imports`, `inherits`, `calls` (name-resolved), each tagged `EXTRACTED` or `INFERRED` — graphify's confidence tag is the key idea, because it prevents an inferred call from being treated as fact.
- Commands: `graph path A B` (BFS), `graph explain X`, `graph query "<keywords>"` (scoped subgraph). Refuse ambiguous names with candidates and distinct exit codes (graphify uses 3/4), matching AIKit's 0/1/2 contract by treating 3/4 as documented operational results.
- Adopt graphify's "query before grep" nudge as one line in the skill/rules, not a hook.
Skip communities/Leiden — that needs optional deps and AIKit's zero-dependency rule wins.

**4. `aikit review` (ponytail's rebuilt review)**
Ponytail's real innovation isn't "write less"; it's that the review reads the code the change *touches*, not just the diff, and each finding states what the code does, what breaks, the fix, and the cost of skipping. AIKit's P-003 R2 demands a call-site check but gives no artifact. Once #3 exists, `aikit review --uncommitted` can deterministically report: changed symbols → reverse dependencies (importers/callers) → tests referencing them → untouched files whose behavior changes → findings missing a covering test. That is a genuine operationalization of P-003 R2 and P-014, and it complements `verify_commit.py` (which verifies the commit alone, not its blast radius).

**5. Reuse ladder (cheapest win)**
Add Ponytail's ordering to P-009 or P-012 capsule text: need-to-exist → already in this repo → stdlib → platform feature → declared dependency → one line → minimum that works, with trust-boundary validation/security never cut. But capsule edits cost budget: `sync_principles.py --check` will force you to condense existing narrative. Do this only alongside a principle revision + ADR, since it is a Track C rule change.

## What not to copy

- **Ponytail's `shortcut:` debt ledger** — conflicts directly with P-007 R3 ("no TODO or stub"). Reframing it as a tracked deferral register would legitimize exactly what AIKit forbids. Skip unless you deliberately relax P-007.
- **Ruflo swarms / vector memory / federation** — requires external services, embeddings, and crypto; violates stdlib-only and would dwarf AIKit's scope.
- **dsh-context's dashboard/browser UI** — AIKit is a CLI; only its *metrics model* transfers, not its surfaces.
- **claude-howto's breadth** — AIKit already has the checkpoint, subagent, secret-scan, and CLI pieces; the one transferable mechanism is checkpoint rewind, and even that is safer as a read-only `resume --since-checkpoint` diff than a destructive reset.

## Suggested sequence

1. `aikit audit` (S, aggregates existing gates) and `aikit context` (S–M) — both immediately useful and low-risk.
2. Reuse ladder as a P-012 amendment with an ADR (XS, but budget-constrained).
3. `aikit graph` (M–L), then `aikit review` (M) on top of it.
4. Delegate telemetry (S), then host hooks (S–M) and test-gap reporting (M) only if the first four prove useful.

Implementation notes: all five repos are permissively licensed (MIT/Apache-2.0) while AIKit is AGPL-3.0 — reimplement the mechanisms rather than copying code, and cite the source repo in the ADR. New subcommands belong in `scripts/aikit_cli.py:92` (parser) with logic in a new module, and any new artifact must be added to the `update_knowledge_base.py --check` freshness gate so it cannot silently rot.
